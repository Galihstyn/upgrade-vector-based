## 2024-05-29 - Prevent Open Redirect and Path Traversal in Back Navigation
**Vulnerability:** Open redirect possible through `document.referrer` via unsafe protocol parsing (like javascript: URLs turning origin to null) or protocol relative paths (e.g. `//evil.com`). Additionally, path traversal vulnerability present when building product fallback URLs because `sourceHandle` wasn't URI encoded.
**Learning:** `new URL()` can assign `"null"` string to `.origin` for protocols like `javascript:`, bypassing strict origin checks if compared to a local origin that might happen to be `"null"`. Additionally, assigning the full `.href` of a referrer without reconstructing path segments can lead to executing malicious protocols or open redirects. `sourceHandle` inputs taken from user/bootstrap parameters must always be URI-encoded before being embedded in internal paths.
**Prevention:** To securely redirect using `document.referrer`, check `origin === window.location.origin` AND `origin !== "null"`. Ensure the `pathname` starts with `/` and not `//`. Finally, construct the redirect URL safely using `pathname + search + hash`. Always use `encodeURIComponent` when building internal paths with dynamic parameters.
