## 2024-05-01 - Open Redirect and Protocol-Relative URL Injection in Referrer Navigation
**Vulnerability:** The internal navigation back logic (`handleBackNavigation`) constructed URLs from unsanitized URL parameters (`sourceHandle` appended directly to `/products/`) and redirected based on `document.referrer` by directly assigning `referrerUrl.href` to `window.location.href`, with insufficient validation of `document.referrer`.
**Learning:** Even when checking that `referrerUrl.origin === window.location.origin`, there's a risk of the origin being `"null"` (like `javascript:` URIs depending on the browser/parsing), and using `referrerUrl.href` directly instead of path components increases the attack surface. Furthermore, appending variables to URL paths without URL encoding can cause path traversal, XSS, or open redirects. Protocol-relative URLs (`//example.com`) can bypass `origin` checks if constructed dynamically.
**Prevention:** Always use `encodeURIComponent()` when appending user-controlled data to path segments. When implementing internal redirects with `document.referrer`, check that the origin is not `"null"`, ensure the pathname starts with exactly one slash (e.g. `!pathname.startsWith("//")`), and only redirect using the path components (`pathname + search + hash`) rather than `href`.
