## 2024-05-18 - [Fix Open Redirect and Path Traversal]
**Vulnerability:** The back navigation logic constructed URLs using unsanitized user input (`productHandle`) and loosely validated `document.referrer`, allowing potential path traversal and open redirects (including `javascript:` URI execution).
**Learning:** `new URL(document.referrer, window.location.origin)` isn't safe if `document.referrer` is a `javascript:` URI (origin becomes `"null"`). Additionally, checking `referrerUrl.origin === window.location.origin` is insufficient because a double slash pathname like `//attacker.com` acts as a protocol-relative URL when assigned to `window.location.href`.
**Prevention:** Always encode user input via `encodeURIComponent` when embedding it in URL paths. When performing relative redirects, verify that `origin` is strictly not `"null"`, that `pathname` safely starts with `/` and not `//`, and only construct the redirect URL from the `pathname`, `search`, and `hash` components.
