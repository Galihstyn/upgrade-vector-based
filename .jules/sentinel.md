
## 2024-05-24 - Open Redirect and Path Traversal in Back Navigation
**Vulnerability:** The `handleBackNavigation` function in `app32825_FIXED.jsx` was vulnerable to path traversal because user-controlled `productHandle` was directly appended to `/products/` without URL encoding. It was also vulnerable to open redirects and protocol relative attacks due to unsafe parsing and use of `document.referrer` combined with full `referrerUrl.href` assignments to `window.location.href`.
**Learning:** `new URL(document.referrer, window.location.origin)` does not completely neutralize malicious `javascript:` URIs (which can return an origin of `"null"`) or `//` protocol-relative paths if directly assigned to `window.location.href`. Also, user-provided inputs like handles used in URL construction must always be URL-encoded.
**Prevention:** Always use `encodeURIComponent` when appending dynamic inputs to a path. For internal redirects using parsed URLs, verify that the `origin` exactly matches the app's `window.location.origin` (and is not `"null"`), ensure the path starts with exactly one slash, and redirect strictly using path components (`pathname + search + hash`) rather than the full `.href`.
