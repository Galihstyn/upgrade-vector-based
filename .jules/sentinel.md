## 2024-05-22 - Prevent Open Redirect and Path Traversal in Back Navigation
**Vulnerability:** The back navigation handler in `app32825_FIXED.jsx` constructed fallback URLs by directly interpolating an unsanitized `productHandle` string (`/products/${sourceHandle}`). Furthermore, it relied on `window.location.href = referrerUrl.href` for `document.referrer` based redirects without fully restricting protocol-relative injections or checking against `"null"` origins.
**Learning:** Even when reading from a supposedly safe `themeBootstrapRef` or `document.referrer`, strings must be encoded before being used in URL construction. Relying on `URL.origin` checks alone doesn't prevent all types of malicious redirects, such as those exploiting `javascript:` URIs (where origin is "null") or absolute URI overrides if the full `.href` is used.
**Prevention:** Always use `encodeURIComponent()` when interpolating URL path parameters. When implementing internal redirects, strictly construct the target using only safe path components (`pathname + search + hash`) and validate that `pathname` begins with a single slash (and not a double slash) to prevent protocol-relative escapes.
