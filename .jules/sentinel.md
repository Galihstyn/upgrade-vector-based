## 2024-05-30 - Prevent Open Redirect via `javascript:` URIs Evaluating to "null" Origin
**Vulnerability:** The internal routing implementation for 'go back' actions used `referrerUrl.origin === window.location.origin` as a check. However, in certain cases, especially with `javascript:` URIs, the origin is `"null"`. Additionally, relying on `referrerUrl.href` could be unsafe or lead to open redirects/protocol relative URL injections (e.g., `//malicious.com`).
**Learning:** `new URL` handles `document.referrer` somewhat permissively. A `javascript:` URI can produce a "null" origin that might bypass standard checks, and simply redirecting to `.href` allows arbitrary protocols.
**Prevention:** Always verify that `origin !== "null"`. Restrict redirect targets by constructing paths safely using `pathname + search + hash` instead of the full `href`, and strictly validate that `pathname` begins with a single `/` and not `//` to avoid protocol-relative URLs. Use `encodeURIComponent()` when substituting user variables like `productHandle` into URL paths.
