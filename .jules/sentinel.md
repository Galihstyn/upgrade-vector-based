## 2024-05-14 - Prevent Open Redirect and Path Traversal in Back Navigation
**Vulnerability:** Internal routing logic used `window.location.href` with unencoded, user-controlled parameters (`productHandle`), risking path traversal and XSS. Additionally, `document.referrer` redirects used full `href` without verifying `pathname` starting with a single `/`, risking protocol-relative injection or bypasses.
**Learning:** URL parameters mapped to internal paths must always be sanitized using `encodeURIComponent()`. Redirects derived from `document.referrer` should explicitly use path components (`pathname + search + hash`) rather than the full `.href` to enforce same-origin constraints even if the origin check is bypassed.
**Prevention:** Always use `encodeURIComponent()` when interpolating URL parameters into paths. For internal redirects, validate `referrerUrl.origin !== "null"`, ensure `pathname` starts with `/` and not `//`, and reassemble the safe path components instead of blindly trusting `.href`.
