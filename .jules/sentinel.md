## 2025-05-27 - [CRITICAL] Prevent Open Redirect & Path Traversal in handleBackNavigation
**Vulnerability:** The application was using un-sanitized url parameters to build the fallback product link via template strings (e.g. `/products/${sourceHandle}`). Additionally, it redirected users to the full `referrerUrl.href` even though the URL origin could be null (like in a `javascript:` uri context) and `referrerUrl.pathname` could be `//malicious.com`, bypassing the domain matching check.
**Learning:** React Router and window.history won't inherently protect you from open redirects when falling back directly to `window.location.href`. Also, Javascript's `URL` class parses `javascript:` origin as "null" which can unintentionally bypass basic domain verification.
**Prevention:** Always use `encodeURIComponent` when interpolating variables into URL paths to prevent path traversal issues. Secure internal redirects by strictly checking that `referrerUrl.origin !== "null"` and `pathname.startsWith("/") && !pathname.startsWith("//")`. Only use the `pathname + search + hash` combination for internal redirects instead of `href` to avoid protocol-relative injections.
