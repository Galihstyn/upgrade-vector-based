
## 2024-05-25 - Open Redirect/XSS via Null Origin Referrer
**Vulnerability:** The `handleBackNavigation` function used `document.referrer` to perform an internal redirect. It validated the domain by checking `referrerUrl.origin === window.location.origin`. However, if the page was accessed via a `data:`, `file:`, `javascript:`, or sandboxed context, `window.location.origin` could be `"null"`. An attacker could exploit this by providing a `javascript:alert(1)` referrer, whose origin is also `"null"`, making `"null" === "null"`. The code then directly set `window.location.href = referrerUrl.href`, leading to XSS or an open redirect.
**Learning:** `new URL()` can parse `javascript:` URLs, and their `.origin` property evaluates to `"null"`. An exact string equality check on origins is insufficient if the current window origin itself is `"null"`. Additionally, redirecting using `.href` directly passes full protocol/domain control to the parsed URL if the origin check is bypassed.
**Prevention:** Always check that the parsed `URL` object's `origin` is not `"null"`. Crucially, only perform internal redirects using the path components (`pathname + search + hash`) while explicitly validating that the `pathname` starts with a single `/` and not `//` to prevent protocol-relative URL injection.
