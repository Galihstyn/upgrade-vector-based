## 2024-05-31 - Fix Open Redirect and XSS in Internal Redirects
**Vulnerability:** The internal redirect logic in `handleBackNavigation` (using `document.referrer`) was vulnerable to open redirects and XSS. An attacker could use a URL like `//evil.com` which bypassed the origin check and allowed redirection to external domains, or `javascript:alert(1)` which produced a `"null"` origin in some environments resulting in XSS.
**Learning:** `URL.origin` checking alone is insufficient because `new URL("//evil.com", "https://example.com").origin` can incorrectly be parsed depending on the input string, or evaluate to `"null"` for `javascript:` URIs. Also, assigning the full `referrerUrl.href` when only an internal path change is desired opens up protocol-relative URL injection.
**Prevention:** To securely implement internal redirects via `document.referrer`, check that the parsed `URL` object's `origin` matches `window.location.origin` and is not `"null"`. Crucially, only redirect using the path components (`pathname + search + hash`) while validating that `pathname` starts with a single `/` and not `//` to prevent protocol-relative URL injection.
