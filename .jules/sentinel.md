## 2024-XX-XX - Fixing Referrer Redirection Logic
**Vulnerability:** The internal redirect mechanism relies on `document.referrer`. Although checking `referrerUrl.origin === window.location.origin` adds some protection against cross-site redirect, it is safer to only use the path components (`pathname + search + hash`) from the `referrerUrl` to perform the redirect, and to explicitly verify that the `origin` is not `"null"`. Additionally, it must enforce that `pathname` starts with exactly one slash, preventing protocol-relative redirection inside the path. Similarly, `safeFallbackProductUrl` relies on user input (`sourceHandle`) which should be properly URL-encoded using `encodeURIComponent()` to avoid Path Traversal and Open Redirects via manipulated inputs.
**Learning:** URL components `origin` can be `"null"` (string) in modern browsers for `javascript:` or `data:` URIs. Interpolating unsanitized handles straight into URL paths can be dangerous.
**Prevention:** Always use `encodeURIComponent()` for URL parameters and perform strict validation when dealing with `document.referrer` for redirects.
