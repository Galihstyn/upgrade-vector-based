## 2024-05-25 - DOM-based Open Redirect and Path Traversal via document.referrer and unsanitized parameters
**Vulnerability:** The application was vulnerable to path traversal via an unencoded user-provided `productHandle` and DOM-based Open Redirect because it blindly trusted `document.referrer` properties (`referrerUrl.href`) without verifying the protocol scheme or validating the path properly.
**Learning:** `new URL()` handles malformed URLs like `javascript:alert(1)` by setting `origin` to `"null"`. Additionally, assigning strings like `//evil.com` as path components can result in protocol-relative URL injection. Furthermore, any user-provided string used as a URL parameter should be encoded using `encodeURIComponent` to prevent path injection like `../../`.
**Prevention:** Always check `referrerUrl.origin !== "null"` along with `referrerUrl.origin === window.location.origin`, reject any path starting with `//`, and only construct redirects using safe path components (`pathname`, `search`, `hash`). Use `encodeURIComponent` for any user-provided strings mapped to internal URL path segments.
