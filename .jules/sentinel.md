## 2024-05-24 - [Fix Open Redirect and Path Traversal in handleBackNavigation]
**Vulnerability:** The `handleBackNavigation` function was vulnerable to path traversal via the `sourceHandle` parameter when constructing the `safeFallbackProductUrl`. Additionally, the fallback redirect logic using `document.referrer` was susceptible to Open Redirect or `javascript:` execution if `referrerUrl.origin === "null"` (e.g., from an iframe or data URI), and protocol-relative URLs (`//evil.com`) could be injected via `referrerUrl.pathname`.
**Learning:** Checking `referrerUrl.origin === window.location.origin` is insufficient to prevent all forms of open redirect or script execution if the origin resolves to `"null"` (which matches `window.location.origin` if it is also `"null"` or in certain contexts) or if `referrerUrl.href` is used directly allowing `javascript:` URIs depending on browser handling. Furthermore, using un-encoded user input directly into a path can easily lead to path traversal (e.g., `../../../`).
**Prevention:** Always use `encodeURIComponent` when embedding dynamic values into URL paths or queries. For internal redirects using `document.referrer`, explicitly reject `"null"` origins, verify the origin against `window.location.origin`, and construct the target URL safely by combining `pathname + search + hash` instead of using the raw `href`, while enforcing that the `pathname` starts with a single `/` and not `//` to block protocol-relative redirects.
