## 2025-02-24 - Expensive Refs Lazy Initialization Anti-Pattern
**Learning:** Using `useRef(expensiveFunction())` in a React component initializes the ref with the correct value on the first render, but it continues to call `expensiveFunction()` on *every single re-render* before discarding the result. In complex components like `AppContent` in `app32825_FIXED.jsx`, functions like `getThemeBootstrap()`, `safeClone()`, and `buildProjectStorageKey()` were being repeatedly and unnecessarily executed, wasting CPU cycles on heavy DOM queries and JSON parsing during every interaction (e.g., selection changes, typing).
**Action:** When initializing a `useRef` with an expensive computation, always use the explicit boolean guard pattern: `const isInitialized = useRef(false); if (!isInitialized.current) { ref.current = expensiveFunction(); isInitialized.current = true; }`. This guarantees the expensive function runs exactly once during the initial mount, avoiding silent performance degradation on hot paths.
